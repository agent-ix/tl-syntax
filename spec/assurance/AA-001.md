# tl-syntax v0.1 source-release argument

## Claim

The open claim concerns only the exact source and corpus revisions presented to
the human release owner under AP-001. It excludes crates.io publication and
downstream semantic correctness.

## Reasoning

Structural validation, strict identity/version boundaries, complete requirement
bindings, feature checks, and corpus tests address the declared deterministic
failure scenarios. Independent human review owns the final sufficiency judgment.

The committed `evidence/ANCHORS` manifest is an in-repository integrity
boundary protected by Git history and pull-request review. It detects
unreviewed record or checksum drift, but is not an external timestamp,
notarization, or independent attestation. Regenerating both a record and its
anchor therefore remains a review-visible source change; the human release
owner must assess that diff and the named source revision.

The executable identities in `tools.lock` describe one qualification host, not
a portable build environment. An independent reviewer can run ordinary source
CI and re-derive the retained record, parameter set, launcher digests, and
dispatched Rust-toolchain identity without possessing those absolute paths; a
new evidence collection requires the named host profile. Its dedicated ignored
Cargo target is cleared before collection, excluding shared ambient build-cache
state from the qualification inputs. This qualification PR
must land with a true merge commit, making its bound revisions ancestors of
`main`; squash and rebase merges are outside the assurance boundary. The source
branch must also be retained until all downstream pins and records have moved to
reachable main revisions.

## Sufficiency Decision

The claim remains open until the retained evidence names the candidate revision,
all blocking gaps are closed, and the human release owner records an explicit
accept or reject decision. Automated checks cannot change this status.

## Challenges

The shared corpus is designed for downstream adoption, but those repositories'
pinning and evaluator/rewrite results are outside this crate's implementation
boundary and remain visible as a program-level challenge.
