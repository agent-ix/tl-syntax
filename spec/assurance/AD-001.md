# tl-syntax v0.1 architecture

## System Boundary

The crate owns values and structural validation for bounded discrete MLTL,
wire-format version identities, and corpus assets. Callers own storage,
parsing, evaluation, rewriting, runtime monitoring, and the meaning assigned to
proposition observations. The crate also owns a parser-independent declaration
boundary for named, bounded input signals and caller-supplied requirement
context; it does not own IR field derivation, predicate lowering, or the meaning
of a signal value.

## Views

The allocation-free core contains value newtypes, profile enums, node records,
and a borrowed topologically ordered formula view. Borrowed signal declarations,
proposition bindings, and requirement context keep the same no-allocation core
boundary. The optional `alloc` layer owns node, proposition-map, signal-catalog,
and context strings/vectors. The optional `serde` layer adds strict wire enums
and derives. Checked-in JSON fixtures consume that public wire contract and are
verified by integration tests.

## Decisions

Node operands are stable indices into a topologically ordered slice. This avoids
recursive allocation and makes forward or cyclic references locally
rejectable. Intervals and spans use checked constructors. Wire versions and
semantic profiles use closed enums so unknown values cannot silently downgrade.
Signal identities are distinct from proposition identities: propositions may
bind only to declared Boolean signals, while bounded integer and fixed-decimal
signals remain available for a caller's explicit predicate-lowering boundary.
No raw numeric value is coerced to Boolean. Integer and fixed-decimal domain
wrappers validate their own bounds at construction, following the existing
checked Interval and SourceSpan pattern; a public domain value is never waiting
for later catalog validation to become valid.

## Risks

O(n squared) duplicate-name checking in the no-std proposition-map validator is
accepted because maps are fixture and interchange metadata rather than an
evaluation hot path. Deep syntax graphs do not consume stack depth during
validation. The v1 signal vocabulary is deliberately conservative; unsupported
IR scalar kinds are rejected at the future adapter boundary rather than mapped
through an opaque fallback. Schema evolution requires a new explicit enum
variant and review.
