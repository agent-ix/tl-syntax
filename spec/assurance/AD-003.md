# tl-syntax infinite-trace profile architecture

## System Boundary

The crate owns the `UnboundedInterval` value, the `tl-syntax.formula-unbounded/v1`
document edition, and the `tl-syntax.liveness/v1` capability identity a
downstream evaluator registers against. It does not evaluate an unbounded
formula, does not decide fairness or lasso acceptance, and does not own the
`quire.temporal.infinite-trace/v1` QSL member itself, which STD-13 mints and
owns. The TL-native profile identity is `mltl.infinite-trace/v1`.

## Views

`UnboundedInterval` sits beside the existing closed `Interval` (AD-001) as a
second checked value, distinguished at the type level so a caller cannot
construct a document that mixes an open bound into the closed
`tl-syntax.formula/v1` schema. `tl-syntax.formula-unbounded/v1` reuses the
existing future and past node, atomic, and Boolean vocabulary; the interval
field on `F/G/U/R/O/H/S/T` widens to accept either variant. The
`tl-syntax.liveness/v1` registration boundary is a non-wire Rust trait-shaped
contract, structurally parallel to the FR-008 lowering request/report/refusal
contracts already in AD-001's views.

## Decisions

The unbounded grammar is minted as a sibling of formula v1 and v2. Both old
decoders retain their bytes and boundedness guarantee and reject the new
schema string under FR-004's unknown-schema rule. Future and past nodes may
mix only in the infinite-trace edition.

Liveness-capability absence is represented the same way QSL represents solver
absence: a named capability plus an `unsupported` settlement carrying a
warning, never a hold or refusal error. tl-syntax owns the capability identity
so that the identity a downstream evaluator registers against, and the
identity the absence warning names, can never drift apart.

## Risks

No backend registers for `tl-syntax.liveness/v1` until tl-mltl#68/#72 land, so
every `tl-syntax.formula-unbounded/v1` document settles `unsupported` until
then; this is the accepted, specified absence path, not a defect. The interval
value doubling (closed and unbounded) is accepted because it keeps
`tl-syntax.formula/v1` provably finite rather than introducing an optional
upper bound that every existing consumer would need to re-check.
